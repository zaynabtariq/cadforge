# Transactional command composition

`PythonWorkspace.preview_sequence` and `POST /api/sessions/{id}/sequence` compose two to eight existing commands against explicit selections. Every step runs the existing operation validator. Intermediate geometry is isolated; the final accepted output becomes one ordinary preview. Apply increments the live revision once, and one Undo restores the original version. A rejected later step makes the whole preview uncommittable. Stale source revisions reject before execution.

Request body: `{"base_revision":0,"steps":[{"command":{"op":"translate","axis":"x","amount_mm":5},"selection":{"part_id":"..."}},{"command":{"op":"resize","axis":"y","target_mm":20},"selection":{"part_id":"..."}}]}`. Selections use explicit part IDs and world coordinates for each step. This API does not infer that a point or selection should move with a prior edit. Nested sequences are unsupported.

The isolated workspace copies a strategy-store snapshot. Speculative successes do not enter persistent learning. An executed failure of a previously persistent strategy now saves its counterexample and quarantines the priority even if the sequence rolls back. Scratch-only skill IDs cannot enter that path, and a later shared-invariant failure does not count as a local strategy failure. Actual per-step checks, learning hints and repair trials are retained in `step_outcomes`, including failures. Successful composition evidence is not yet promoted into persistent skills. This avoids treating an abandoned intermediate candidate as a completed user operation; trusted composition-learning ingestion remains unfinished.

The live state is unchanged during preview. Committed history retains the sequence, full step outcomes and learning scope, and can be saved in a portable project. Each operation's checks apply at that step; there is not yet a global invariant contract preventing a later intentional command from changing an earlier feature. This is transactional execution infrastructure, not a natural-language sequence planner or inherited engineering-constraint proof. The natural-language/UI path is described below; shared engineering invariants remain unfinished.

Independent regression tests cover same-part chained transforms, one-step Undo, later failure, stale revisions, step limits/nesting and real region-repair isolation. Actual HTTP development evidence in `artifacts/composition/result.json` composes translation followed by a blind hole. An over-deep second hole rejects and retains the original. The successful output is `composed.stl`; both runs use real geometry and zero model calls. No frozen benchmark files or hidden instances changed.

## Plain-language sequencing

The `/edit` flow now recognizes two to eight explicit clauses separated by “then”. Each clause is planned against the isolated workspace after the preceding operation has executed, so repeated relative dimensions accumulate correctly. The UI presents each step and its checks before one Apply. Failed or ambiguous later steps reject the transaction and preserve their clarification in the preview details. Single-operation requests use the existing planner.

Natural-language sequences currently require whole-object selection from the object list. Point/region selections and recognized cross-step preservation constraints request clarification; their moving references and shared invariant contracts must not be guessed. Independent tests confirm an initial 10 mm extent becomes 20 then 30 mm, not 20 twice, and validate rollback and guarded constraints. Completed compositions still do not promote speculative outcomes into persistent learning.

Actual browser evidence: `artifacts/sequence-browser/`. A public plate request, “Make this 1 cm wider then make this 1 cm wider,” produced 203.19999695→213.19999695→223.19999695 mm. Apply and one Undo completed without browser errors. Exact oriented triangle comparison confirms the restored surface, including winding. A first raw-array comparison failed because import changes vertex/index ordering; this diagnostic is retained in `verification.json`. The two model calls used 3,321 tokens. These are development operations, not heldout evaluation; no benchmark score changed.

## Shared hole-preservation contract

The typed sequence API now accepts `invariants: [{"kind":"preserve_holes","part_id":"..."}]`. It captures the original recognized Z-through-hole vertices and oriented protected faces, then requires an exact signature match after **every** step, including STL serialization. Storage-order changes are normalized; coordinate/face changes are not tolerated. Conservative recognition may reject unfamiliar channels or retriangulation. This does not establish arbitrary-hole recognition, strength or general mechanical invariants.

The contract rejects the public plate sequence “protected widening, then translation”: both individual commands pass, but the second moves the protected interfaces. Two protected resizes on X/Y pass. A shift followed by a restoring shift cannot bypass the intermediate checks. Full rollback remains active. Contract definitions and baseline signatures survive commit history; imported history remains unverified provenance.

Public development evidence: `artifacts/composition-invariants/results.json`. The unguarded sequence passes, the guarded version rejects step 2, and the preserving sequence passes without changing the contract or validator. No model calls were used. The supported natural-language preservation phrase is described below; broader invariant language remains unsupported.

## Plain-language shared preservation

Requests ending in “keeping holes fixed throughout” (also “keep … unchanged throughout”, with optional “all”/“mounting”) now explicitly attach the supported global hole contract. X/Y resize steps use the existing protected-rail operation with the computed target retained and a 1 mm support margin. Other steps still face the same global invariant; translation is rejected if it moves holes. Additional unrecognized preservation constraints continue to clarify. Each step's UI description uses its own input bounds, avoiding a misleading original extent on repeated resizes.

This exposed a real inherited-operation failure: the second protected resize rejected with `Band-plane subdivision did not preserve closed topology`. Its cut plane was almost coincident with the first plane after binary STL serialization. `protected_edit.py` now moves each band boundary outward to the next float32 coordinate. This enlarges the support band by at most the outward rounding step rather than reducing its required margin. Coordinates of protected holes and every existing geometry gate remain unchanged. The repeated-operation test now passes; this is a repair to generated geometry, not a relaxed checker.

40 protected-edit/profile/workspace/sequence tests pass. Actual public-STL browser evidence in `artifacts/protected-sequence-browser/` confirms two 10 mm widenings, exactly unchanged recognized hole surfaces, and one Undo restoring exact oriented triangles. Two model calls used 3,311 tokens. The initial subdivision failure is retained as a regression test; authoring costs are not fully metered. Persistent learning from completed compositions remains unfinished.
# Negated shared constraints

A development probe found that “Make this 1 cm wider then make this 1 cm wider, not keeping holes fixed throughout” was accepted as two hole-preserving resizes. The suffix extractor had dropped the scope of “not.” The planner now clarifies negated preservation before any model or CAD execution. Seven regression cases cover negation and unsupported trailing qualifications; the sequence and invariant suites pass 27 tests. This is a bounded language guard, not a claim of complete natural-language constraint understanding.
