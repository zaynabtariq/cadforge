# Counterbores in the editor

Click the flat top or bottom rim of a straight circular Z-through-hole, then request `Counterbore this hole to 8 mm diameter and 2 mm deep`. The planner anchors the recess to one recognized hole center. Additional unsupported instructions request clarification. The operation preserves an open lower bore, checks an annular floor with two boundary loops, verifies removed volume and full annular stock coverage, and rejects material changes outside the tool. Blind-hole checks remain unchanged.

If a healthy learned tool-pocket rule exists, `Counterbore this hole for a 6.5 mm tool with 0.25 mm radial clearance and 2 mm deep` reuses its dimension relation. This is a bounded parser with zero model requests. The rule's ID, input dimensions, output diameter and validator context are retained in the preview and applied history. Its BRep-coupon provenance initializes dimensions; the imported mesh must separately pass counterbore checks. Unsupported parameter ranges clarify instead of extrapolating or silently rediscovering.

The actual browser flow imported a constructed straight-hole fixture, clicked its rim, used that learned request, applied the edit, exported STL and restored exact baseline bytes with Undo. An independent export check measured 51.784410039 mm³ removed versus 51.784409589 mm³ expected, with unchanged bounds and positive watertight topology. The public `plate_holes.STL` has stepped holes and correctly requests clarification. This is not successful arbitrary public-STL counterboring.

The first browser run failed two unchanged geometry checks. The fitted center's roughly 1e-16 mm offset caused Boolean boundary artifacts. The kernel now explicitly records a near-zero machine-roundoff canonicalization, bounded by 16 float64 epsilons times stock coordinate scale. A separate earlier Boolean artifact required reapplying the actual protected polygonal bore after composition; that repair is also recorded. Neither failure was resolved by relaxing check tolerances. These were agent-authored kernel repairs, not runtime model-weight learning.

Twenty kernel tests pass, including the exact browser regression. The combined kernel/planner/archive checks pass 49 tests, and workspace/planner/learning-recovery checks pass 23. An initial test command used the wrong archive filename and ran no tests; corrected suites passed. UI build and actual browser run passed with no page errors. Weave-enabled server execution traced the development route, with no LLM inference for the bounded request.

Evidence: `artifacts/counterbore-browser/initial-failure.json`, `initial-failure.webm`, `result.json`, `export-verification.json`, exported STLs, `preview.png`, and `counterbore-demo.mp4` (13.72 seconds). The new video shows editor reuse, Apply, Undo and unsupported-case handling; the earlier learning-restart video remains the full candidate/promotion/reuse demonstration. Kernel-authoring and test costs are additional to the coupon discovery costs reported in `TOOL_ACCESS_LEARNING.md`.

Scope initially covered straight, coaxial Z-through holes in a single closed mesh. The profile extension below adds selected cylindrical entrances without allowing cuts across existing shoulders or tapers. Oblique and blind bores, arbitrary assembly tool motion and manufacturing qualification remain unsupported. Saved imported history is still unverified provenance, never executable training evidence.

## Public stepped-profile extension

`profile_counterbore.py` reconstructs the selected original cavity from its actual protected wall and shoulder triangles. It supports a new recess strictly within an existing cylindrical entrance segment. Workspace dispatch chooses the straight or profile kernel by recognition before executing an edit; it never retries failed geometry under different checks. Tapered entrances and cuts reaching an existing shoulder reject.

The actual public browser run clicked the rim of the central stepped hole in unmodified `plate_holes.STL` and requested `Counterbore this hole to 15 mm diameter and 2 mm deep`. Preview, Apply, export and exact Undo passed with no page errors. Independent export measurement found 161.095947606 mm³ removed versus 161.095882966 mm³ expected, and all 360 protected source vertices below the new floor or at the other holes unchanged exactly. This explicit-diameter request did not use the learned 4–8 mm tool-diameter rule.

Strict Boolean checks exposed further post-restoration artifacts. Subtracting the complete protected original void and intersecting with the original stock resolved the top-entry case; the initial and final artifact counts remain in feature provenance. A bottom-entry public variant still fails its numerical checks and remains rejected. No tolerance was relaxed to claim support for it.

The combined profile, straight-kernel, planner and workspace suites pass 47 tests. Independent parser review also found strict inequalities being silently interpreted as exact dimensions and an invalid `1/0` fraction causing an uncaught exception; both now clarify before execution. Evidence and the recorded video are under `artifacts/profile-counterbore-browser/`, including `result.json`, `verification.json`, STEP-independent STL measurements and `public-counterbore-demo.mp4`.
