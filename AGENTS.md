# Continuing CADForge

The active objective is reusable engineering learning across objects, with production-ready camera/Pi glasses as the first product. A passing toy benchmark is not completion.

The primary user experience is a general 3D editing workspace: drop an existing STL/STEP, select an object or section, and request edits in plain language. Glasses are an example project, not the main form. Test the actual browser flow with an unrelated public STL. Acceptance also requires a recorded video showing a real failed edit, correction, and a later edit benefiting from persisted learning, with actual evidence and limitations. Do not substitute a scripted animation for the functioning editor.

Save/reopen `.cadforge` projects through the workspace archive boundary to preserve original CAD bytes, applied geometry, active Undo ancestry and reported operation provenance. Validate archives before publishing fresh paths/IDs. Never execute archived commands or promote imported historical checks into trusted learning. Portable mesh history is not a reconstructed native CAD feature tree. See `docs/PORTABLE_PROJECTS.md`.

Start from the persisted learning service (`cadforge.continual`, default database `~/.local/share/cadforge/learning.sqlite3`). Inspect its healthy promoted commands in the exact validator/material/tool context before rediscovering operations. Use `cadforge.evolve` to perform bounded development discovery, challenge, transfer and reuse; record failures and costs. Skills must pass independent counterexamples and cross-task development transfers before promotion. Regressions quarantine a command and its descendants. Never silently extrapolate beyond validated support.

Generic CAD edits must carry invariant contracts: for example, widening a robot arm must preserve pivot axes and center distance. Keep failure-derived operations reusable and test them on another object. Refilling a protected hole after a union is an engineering failure; repair the material, not the checker.

Dimension parsing must consume complete quantities, including leading decimal points, fractions and scientific notation. Never use the first number or first axis as evidence that every requested constraint is covered. Preserve explicit minimum walls, reject conflicting targets, and retain model clarifications rather than replacing them with an incomplete offline command. Regressions and measured failures are in `tests/test_measurement_intent.py` and `artifacts/measurement-intent/`.

Imported whole-part widening with explicit hole preservation now uses `resize_preserving_holes` and conservative complete coaxial Z-through-profile recognition. Never silently replace that request with generic scaling. Unsupported orientation/topology must be surfaced. Preserve full wall/shoulder coordinates and split triangles at deformation boundaries before moving rails. See `docs/PROTECTED_EDITS.md` for the numerical policy and actual public-STL evidence. Preview plans must target their source revision; concurrent changes invalidate old plans.

Requested blind-hole depth is measured inward from the clicked surface, never half the height of a centered cutter. Use `drill_blind_hole` for supported Z top/bottom entries. Require the actual cavity floor to be a disk without inner openings and full inward-tool coverage by stock; aggregate area/volume alone missed a real tiny-through-hole counterexample. See `docs/BLIND_HOLES.md`. These faceted-mesh checks remain bounded by kernel resolution and do not qualify fabrication.

For other selected planar exterior support faces, `drill_surface_hole` composes the same blind operation in a local frame using the actual clicked normal. Preserve explicit precision-normalization metadata and the final original-stock volume gate; all inherited checks stay active. Do not substitute Z drilling when a side normal or explicit orientation is supplied. See `docs/SURFACE_HOLES.md` for numerical repair limits and the distinction between local and final world checks.

The original v1 benchmark/result is archived. Do not edit `benchmark.py`, `benchmark_reference.py`, `schema.py` or `benchmarks/`, inspect private instances, or ingest v1 heldout results into learning. Use fresh development cases and newly versioned evaluation contracts for further research.

Use the production geometry backend and independent engineering gates. Keep `pass`, `fail`, and `blocked` separate. CAD clearance and nominal material screening do not prove manufacturing capability, fastener strength, cable fatigue, optics, thermal performance, or wearer fit. Preserve editable source and STEP/STL exports. User instructions supersede this guidance.

Engineering contracts and computed gate values must remain finite; an infinite support coordinate previously produced a false zero-load pass. Reject invalid contracts before measurements, and retain overflow checks. Nominal reference mass is an incomplete inventory estimate, not measured worn mass or release evidence; use `scripts/screen_reference_mass.py` and `docs/MASS_SCREENING.md` with the source-versioned material assumptions.

W&B development traces belong to the configured `cadforge-continual` project. Credentials are in the macOS Keychain/environment, never source or CAD artifacts. The `wandb` remote MCP entry queries observability; `cadforge` exposes the local engineering tools. Avoid hidden-data cloud traces. Use tests appropriate to each changed operation and retain measured before/after evidence.

Explicit rigid selected-section translation uses `translation_mode: rigid`; never satisfy it by tapering displacement. Preserve that contract after model planning and ignore incompatible learned priorities. The executor permits only direct displacement and checks every selected vector; failed rigid edits remain uncommittable. See `docs/RIGID_TRANSLATION.md`.

Cable straightness must be scale-independent: compare normalized segment directions, not raw cross-product magnitude. Reject nonpositive radii/bend limits and duplicate segments before CAD measurements; missing supplier limits remain blocked. See `docs/CABLE_CONTRACTS.md` for reproduced false passes and numerical scope.

Counterbores use separate checked mesh kernels: `counterbore.py` for straight through-bores, `profile_counterbore.py` for a cylindrical entrance segment of a recognized coaxial profile. Select the kernel by recognition before execution; never retry a rejected edit under weaker checks. Preserve the complete original bore void, outside stock and annular floor. Crossing an existing shoulder or taper remains unsupported. Record machine-roundoff normalization and actual protected-void repairs. The learned tool-pocket relation initializes dimensions within its original context/ranges; imported mesh success is not automatically new training evidence. See `docs/COUNTERBORES.md` and the retained public-STL tests.

Protected imported widening now composes the original Z-profile kernel through exact cyclic axis permutations in `axial_protected_edit.py`. Recognition chooses one unambiguous coordinate-aligned bore direction before execution. Never retry failed geometry in another frame or approximate an oblique rotation. Sequence invariants hash original protected world vertices and oriented triangles after every step; see `docs/PROTECTED_EDITS.md` for rotated public-STL browser evidence.

Protected height requests now use the same exact axis-permutation operation as width/depth. Accept X/Y/Z only when perpendicular to the recognized bore; keep bore-parallel rejection in the executor. See `scripts/test_axial_height_browser.mjs` and `scripts/verify_axial_height.py` for the actual browser/export/Undo check.
